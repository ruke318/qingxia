# 主入口实施计划

状态：已进入开发与原生验证阶段，实际进度见[任务跟踪](任务跟踪.md)。

技术方案：Tauri 2 + React + TypeScript + Rust + SQLite。

## 一、当前范围

- 主入口采用 macOS 聚焦搜索式悬浮输入框。
- 目录到达与文件搜索由宿主内置实现，不依赖插件。
- 剪贴板、hosts、JSON 等工具后续通过插件扩展，当前不讨论插件界面。
- [第二版概念图](design/ui-concept-v2.png)仅以左侧输入框作为视觉方向参考；实际尺寸以本计划为准，右侧插件界面不纳入当前范围。

## 二、尺寸、定位与视觉

| 项目 | 当前规格 |
| --- | --- |
| 输入框宽度 | 当前屏幕逻辑宽度的 1/3，最小 720px（逻辑像素） |
| 输入框高度 | 初始高度 60px；实现按 60 个逻辑像素处理 |
| 水平位置 | 在当前屏幕内水平居中 |
| 垂直位置 | 输入框中心位于当前屏幕可用高度的 1/3 处 |
| 形态 | 单块悬浮毛玻璃面板，无标题栏、红黄绿按钮和永久导航栏 |
| 拖动 | 可按住输入框空白区域拖动；输入框、输入文字、按钮和结果行保持正常点击与输入 |
| 初始透明度 | 原生毛玻璃材质保持完整强度，叠加 36% 白色遮罩，减弱背景透视；文字和图标独立保持清晰 |
| 圆角 | 18px，原生内容层同步裁切；保留低对比细边线，移除造成底部黑白条的叠加阴影 |
| 空输入状态 | 只显示输入框，不展示插件列表、推荐卡片或结果面板 |
| 输入占位文字 | 搜索应用、文件或目录… |
| 有结果状态 | 在输入框下方向下展开同一面板，输入框位置与 60px 高度保持不变 |

尺寸与上方 1/3 位置来自已确认要求；坐标口径、圆角和透明度为当前实现默认值。以可运行原型在真实壁纸上的观感进行调整。

目标屏幕默认取唤起时鼠标所在显示器；宽度使用完整屏幕逻辑宽度，垂直位置使用排除菜单栏与 Dock 后的可用高度。macOS 使用 AppKit 逻辑坐标读取鼠标所在屏幕，支持负坐标和混合缩放；实机多屏验收仍需单独记录。不同显示器的坐标原点与缩放比例应分别处理。

设屏幕左边界为 `x0`、逻辑宽度为 `W`，可用区域顶部为 `y0`、可用逻辑高度为 `H`，输入框尺寸与左上角为：

```text
输入框宽度 = max(round(W / 3), 720)
输入框高度 = 60
输入框左侧 = x0 + (W - 输入框宽度) / 2
输入框顶部 = y0 + H / 3 - 30
```

60px 指前端逻辑尺寸；在 Retina 显示器上由缩放比例映射到物理像素。展开结果时保持输入框顶部固定，并根据剩余可用高度限制结果区，超出部分滚动。

透明效果通过背景材质与遮罩实现，不将整个窗口连同文字一起降低透明度。毛玻璃必须能模糊实际桌面背景，在原生 Tauri 窗口中验收。

## 三、可配置唤起快捷键

- 默认建议为 `⌥Space`，作为实现初始值，用户可修改。
- 从菜单栏的“设置”进入快捷键配置，使用按键录入方式修改。
- 修改时检查内部冲突与系统注册结果，注册成功后持久化到 SQLite 并启用。
- 更换失败时保留原有有效绑定；首次注册失败时仍可从菜单栏打开主入口和设置。
- 重启应用后恢复已保存的绑定，不覆盖其他应用或系统已有快捷键。
- 唤起后立即聚焦输入框；主入口已经显示时再次触发，聚焦现有输入框，不生成新窗口。
- 输入框空白区域支持拖动窗口；拖动不会触发打开、隐藏或提交搜索。重新通过全局快捷键唤起时，回到当前显示器默认位置。
- 按 Esc 隐藏入口，应用保持后台运行；输入法组合输入期间优先遵循输入法行为。

## 四、两项内置能力

### 目录到达

- `/` 或 `~/` 开头的输入进入路径补全。
- 输入完整且存在的目录时，将该目录自身放在第一项，回车直接打开；下方同时列出子目录和文件，已取出的子项按目录优先、名称排序。
- 包括目录自身在内最多显示 50 项；多取一项判断是否截断，达到上限便停止枚举，不统计全部匹配数量。更多匹配通过更精确的路径筛选。
- 部分路径同时匹配目录和文件；目录可用 Tab 继续补全下一级。
- 输入普通目录名称时，通过文件搜索找到目录结果。
- 回车在访达中打开所选目录，结果显示名称和完整路径以区分同名项。
- 验证中文目录、空格路径、不存在路径及访问失败。

### 文件与应用搜索

- 普通关键词查询应用、文件和目录，第一版接入 Spotlight 元数据索引；联合文件名和系统显示名匹配，支持“微信”“计算器”等中文应用名。
- 应用独立取候选，避免普通文件先占满名额；应用精确名称优先，并使用系统真实应用图标；回车启动，Tab 不进入应用包内部。
- 查询端限制数量，最多显示 50 项；有更多匹配时提示输入更精确的关键词，不收集全量结果或添加搜索结果缓存。
- 结果显示图标、名称及所在路径，支持打开和在访达中显示。
- 查询异步执行，并取消或忽略过期查询结果。
- 中文输入法组合期间暂停查询与原生窗口尺寸调整，选词结束后查询最终中文，选词按键不得触发结果打开。
- 未索引位置或权限限制导致的缺失需要明确说明；首期不开发全磁盘自建索引或文件正文全文搜索。

## 五、实施与验收顺序

可执行任务、并发依赖和逐步骤状态统一记录在[任务拆分与状态跟踪](任务跟踪.md)。以下为交付顺序；同一阶段内按任务表并发执行。

1. **工程与原生验证**：初始化工程，验证无标题栏透明窗口、真实背景模糊、全局快捷键、拖动及焦点行为。
2. **主输入框与快捷键设置**：按尺寸和位置公式实现输入框，接通快捷键录入、冲突提示与持久化。验收后确认真实桌面观感。
3. **目录到达**：实现路径识别、目录补全及访达打开，验证中文、空格、同名目录和失败提示；与文件搜索及结果列表并发开发。
4. **文件搜索**：接入 Spotlight，与目录到达及结果列表并发开发，再统一联调异步结果、选择、打开和显示所在目录。
5. **主入口整体验收**：检查多屏与 Retina 缩放、全屏应用、拖动、结果展开、上下选择、Esc、快捷键重启恢复，以及中文输入法选字时回车不误执行。

第一份可评审成果是实际运行的毛玻璃输入框与可配置快捷键。该阶段不要求任何业务插件可用，也不以生成图代替真实窗口验证。
