# 偶发无法唤起主入口：2026-10-09

## 现场证据

- 用户看到的现象是完全没有输入框；截图、全屏应用和桌面切换、解锁或输入法相关操作都发生过，尚不能确定触发条件。
- 安装版进程仍在。主线程采样停在正常的 AppKit 事件循环等待，没有发现死锁；主窗口仍存在，检查时处于隐藏状态。
- 检查时系统安全输入未启用；这不能证明故障发生时的状态。
- 14:25 至 14:26，用户重新操作后，日志记录 `Alt+Space → launcher → 显示面板`，用户确认可以正常唤起，随后也能进入插件。期间没有重启或修改安装版。
- 因故障已自行恢复，现有证据不足以认定快捷键、Spaces 或截图收尾中的某一处为根因。

## 本次改动

- 补上 macOS `RunEvent::Reopen`：常驻进程再次从访达或系统搜索打开时，执行现有主入口唤起流程。
- 原来只记 `isVisible` 和键盘焦点；现在同时记录应用是否隐藏、窗口是否最小化、是否在当前桌面、系统遮蔽状态中的可见标记，并在唤起过渡期后再记录一次。
- 主页面处理 `launcher-focus`、聚焦及选中输入框后，立即回报焦点与页面内可见状态。回报不依赖动画帧，不包含搜索内容。
- 主窗口或页面缺失、聚焦失败、没有屏幕、事件发送失败均留下日志。

页面回报只证明页面处理了事件和当时的 DOM 状态；系统可见标记也不能代替实际画面验收。新增的恢复入口修补了确定存在的行为缺口，但不能据此宣称此次间歇性故障已经根治。

- 新增浏览器用例先失败再通过：动画帧暂停时仍能回报、反复唤起并保留选中搜索词、从设置返回主入口，共 3 项；快捷键设置 9 项回归通过。

- 前端及 macOS 应用包构建通过。构建仍有原有 Wry 弃用警告及插件包体积提示。
- 已使用与安装版相同的本地签名更新 `/Applications/轻匣.app` 并启动。新旧包的签名要求相同，完整性验证通过；旧版备份位于 `/private/tmp/qingbox-launcher-backup-51kon60i/轻匣.app`。
- 更新后界面操作通道可用。14:43:08、14:43:18 两次系统重新打开事件均到达新处理逻辑，主页面回报输入框焦点为真，600 毫秒复查记录当前桌面与屏上可见均为真，界面树显示输入框。
- 工具按键前会自动重新打开目标应用，上述证据只能证明重新打开入口生效，不能当作系统全局快捷键验收。跨 Spaces、睡眠恢复、截图取消后的反复唤起仍待实际验证，原偶发故障未复现。

## 再次出现时

先记下时间并分别试一次快捷键、菜单栏「匣 → 打开轻匣」。将该时间附近的快捷键入口、原生显示与复查、页面回报对应起来，确定事件断在哪一层后再修改对应逻辑；不要仅凭“窗口自报可见”判断用户已经看见输入框。
