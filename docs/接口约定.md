# 主入口接口约定

本章描述主入口的宿主内置能力；插件与宿主之间的接口见文末“插件消息协议 v1”。前端统一通过 `src/lib/bridge.ts` 调用，数据定义位于 `src/lib/types.ts` 和 `src-tauri/src/contracts.rs`。

## 宿主命令

| 命令 | 入参 | 返回 |
| --- | --- | --- |
| `get_settings` | 无 | `AppSettings`：快捷键及注册错误 |
| `save_shortcut` | `shortcut` | 保存成功后的 `AppSettings`；失败拒绝并保留旧绑定 |
| `hide_launcher` | 无 | 隐藏主入口 |
| `resize_launcher` | `height`，逻辑像素 | 调整整个面板高度；输入行顶部固定 |
| `open_settings` | 无 | 在同一原生窗口内展开设置面板 |
| `close_settings` | 无 | 收起设置面板并返回主入口 |
| `complete_directory` | `query`、`requestId`、`limit` | `QueryResponse` |
| `begin_search_session` | 无 | 后端分配的数字会话标识 |
| `search_files` | `query`、`requestId`、`querySession`、`limit` | `QueryResponse` |
| `get_application_icon` | 已存在应用包的绝对路径 `path` | 64 × 64 PNG 数据地址 |
| `open_path` | `path`、`reveal` | 打开路径，或在访达中显示 |

`QueryResponse` 包含查询标识、结果列表和可选提示；结果包含名称、完整路径、父路径及 `application`／`directory`／`file` 类型。所有用户可见错误采用中文。前端对比最新查询标识，忽略过期结果。

`complete_directory` 对完整存在的目录返回“目录自身、已取出并排序的子目录和文件”；部分路径匹配目录和文件，自身同样计入限额。两种查询的 `limit` 均限制为 1～50；目录枚举最多多取一项以判断截断，不统计总数。应用包按 `application` 标识，回车通过系统打开，Tab 仅用于普通目录。

浏览器模式仅用于视觉预览，不模拟成功的系统快捷键注册、真实文件搜索或文件打开。

## 事件

- `launcher-focus`：原生窗口唤起后通知前端聚焦输入框。
- `show-settings`：菜单栏通知前端切换到设置面板。
- `settings-changed`：保存成功后通知界面刷新快捷键显示，载荷为 `AppSettings`。

## 当前实现位置

- macOS 窗口定位、材质与非激活 NSPanel 位于 `src-tauri/src/native_window.rs`；SQLite 设置、系统快捷键和目录命令位于 `src-tauri/src/lib.rs`。
- 前端 `Launcher`、`ShortcutSettings` 和结果行暂集中在 `src/App.tsx`，样式位于 `src/styles.css`。
- 首版仅保留已使用的类型与桥接层；后续内置能力成熟后再按任务范围拆文件，尚未创建计划中的各模块目录。
- 文件搜索位于 `src-tauri/src/search.rs`，联合系统索引与常用目录文件名检索。Spotlight 文件名和显示名查询不限定目录或深度；补充检索范围为桌面、文稿、下载及其非隐藏子目录。按路径去重并优先保留索引的本地化名称，应用优先，其后为目录和文件；总计最多 50 项，通过 `notice` 说明截断、无匹配、检索范围和未完成情况。
- 原生索引适配位于 `src-tauri/src/search/spotlight.rs`，应用与非应用两类 `MDQuery` 在专属后台任务的同一线程创建、共用 RunLoop、停止并释放；每轮约 10 毫秒检查取消和 4 秒总期限，活动许可由工作线程持有。
- 批次以 `limit + 1` 为目标，收到足够候选或查询完成便停止；系统批次可能超过该数量，每类只读取至多 51 个候选的元数据，应用候选不会被普通文件挤掉；应用精确名称优先，再合并返回至多 50 项。不使用当前系统上会漏掉微信输入法的 `MDQuerySetMaxCount`。
- 搜索在后台先打开桌面、文稿、下载目录，建立当前进程对已授权目录的访问资格；不缓存授权状态，失败目录通过 `notice` 提示。访问等待受外层 4 秒超时和取消约束，工作线程及其文件名检索结束前始终持有许可。索引结果不逐项检查磁盘属性；路径从单属性接口读取以保留用户路径，名称和类型取系统元数据。目录到达仍会按目标路径检查访问能力。
- `src-tauri/src/search/filenames.rs` 与原生索引查询并行，每次实时枚举文件名、检查目录条目类型，不读取文件正文。按层优先检查各常用目录的直属项目，无固定深度限制；最多取 51 个匹配，单次枚举最多 500 毫秒，每个条目检查取消。隐藏项目及应用/框架包内部交由索引查询，符号链接不递归。未完成枚举或部分目录不可读时标记部分结果，不把未完整查询描述为确定没有文件。
- WebView 初始化时调用 `begin_search_session`；后端只接受当前会话中递增的请求编号，旧会话、同号或更小编号不得取消新请求。前端在当前页面复用初始化 Promise，初始化失败后允许重试；这不是搜索结果缓存。
- 前端请求编号在当前网页生命周期内递增，清空、重新唤起和卸载会使旧响应失效。重新唤起保留搜索词、已有结果和选中项，全选输入并发起新查询；同时重新设置列表高度，避免原生窗口重置为 60px 后裁切结果。最后一个已提交搜索词保存到本地，退出应用重开时恢复并重新查询，不持久化搜索结果。
- 应用图标由 `src-tauri/src/application_icon.rs` 在主线程读取、绘制；前端只请求进入视口的应用图标，最多保留 128 个图标资源，加载失败可重试，图标不阻塞搜索结果显示。
- 输入法组合期间不发新查询、不接收旧结果且不调整原生窗口尺寸；组合结束显式提交最终输入值。

## Hosts 插件接口

- 通过受限的 `plugin_call` 调用 `hosts.get` / `hosts.save`，分别要求插件声明 `hosts.read` / `hosts.write`。插件不能指定任意系统文件路径。
- `hosts.get` 返回分组、系统完整原文 `systemHosts`、用于外部修改检查的 `version`、分组与系统是否一致 `synced`；系统原文在界面只读。
- `hosts.save` 接收 `groups` 和上次读取的 `version`。分组结构为 `{ id, name, content, enabled }`；多个 `enabled: true` 的分组合并写入轻匣管理段。关闭全部分组移除该段，保留其他原文。
- 所有分组均可编辑名称和内容，点击保存或按 `⌘S` / `Ctrl+S` 提交当前分组；修改不会自动提交。已启用分组保存后验证并写入系统，未启用分组只保存本地配置且允许暂存尚未完成的 hosts 行，开启时验证完整格式。开关直接提交当前分组最新内容，其他分组的未保存草稿不随之提交。
- 写入前检查版本、格式、IPv4/IPv6 和同域名同协议地址冲突；后台通过 macOS 系统授权启动当前应用的固定目标写入入口，再次验证原文件哈希，备份后原子替换并刷新 DNS 缓存。不存储管理员密码。
- 备份上限 6 份：首次 `original.bak` 加最近 5 份；新旧内容相同时跳过授权和备份。只轮换自己命名的切换备份，不清理其他文件。
- SQLite 中 `hosts:groups` 为成功应用的配置，`hosts:pending` 为写入前的恢复记录。真实文件匹配目标哈希后才提交分组状态；取消或失败保持原状态。该数据不放入插件通用存储，避免普通存储调用绕过系统写入结果。

## 剪贴板插件接口

- 通过受限的 `plugin_call` 调用 `clipboard.list` / `clipboard.copy`，均要求插件启用且声明 `clipboard.history` 权限。普通 JSON 插件的 `clipboard.writeText` 权限不能读取历史。
- `clipboard.list` 接收 `kind: all | text | image | file` 和可选 `since` 版本号，返回 `{ revision, items, counts, notice }`；版本未变时 `items` 为 `null`，前端保留当前列表。每个分类首次读取不传版本号。`all` 不按类型过滤，按最近时间和记录编号倒序返回最多 200 条，记录自身仍保留原始类型；全部数量为三类计数之和。
- 记录包含 `id`、`kind`、`preview`、`createdAt`、`bytes`、`width`、`height`、`thumbnail`、`files`。文本预览最多 800 个字符；图片只向列表返回最长边 240px 的 PNG 缩略图；文件列表返回绝对路径。原始文本和图片仍保留在宿主数据库中。
- `clipboard.copy` 只接收记录 `id`，由宿主读取真实类型与原始内容，写入 macOS 系统剪贴板。文件按文件 URL 列表恢复；所有路径先验证存在，失败不清空当前剪贴板。复制成功更新记录顺序。
- 宿主使用 [Apple NSPasteboard](https://developer.apple.com/documentation/appkit/nspasteboard) 在主线程读取和写入，每 500ms 检查一次变更编号，按文件、图片、文本的顺序识别。PNG、TIFF、JPEG 图片统一保存为 PNG；内容带隐私、临时、自动生成类型标记时跳过。
- 仅有已启用插件持有历史权限时采集。数据保存在 SQLite 的 `clipboard_history` 表，同类相同内容按 SHA-256 去重，保留最近 200 条且总有效载荷不超过 128 MB；单条上限 20 MB，文本上限 1 MB，图片最多 4000 万像素，一次文件数量最多 100。
- 默认快捷键 `Alt+Shift+V` 只在首次初始化时写入；以后用户修改或清除绑定不会被启动流程重置。分类查询的迟到响应不能覆盖新分类。

## 插件消息协议 v1

本章面向第三方插件作者：只凭本章即可写出、安装和调试一个轻匣插件。协议定义的源码位于 `packages/plugin-sdk/src/protocol.ts`，最小示例插件位于 `examples/minimal-plugin/`（见本章末尾）。

### 1. 工作方式

插件是一个本地目录，包含描述文件 `manifest.json` 和网页资源。用户在主搜索框选中插件命令（或按下为该命令设置的全局快捷键）后，宿主在搜索框下方的内容区用沙箱 iframe 打开插件入口页。插件拿不到任何 Tauri 接口，只能通过握手时宿主交给它的 `MessagePort` 发送请求；宿主校验身份、权限和参数后执行，并经同一端口回传响应和事件。

```text
插件页面（沙箱 iframe） ──MessagePort──> 宿主页面 ──plugin_call──> Rust 网关 ──> 存储、剪贴板、Hosts 等宿主能力
```

插件身份只由宿主为本次打开生成的实例令牌决定；请求参数里出现的插件 ID 一律不作为授权依据。

### 2. 插件包结构与 `manifest.json`

```text
my-plugin/
├── manifest.json      描述文件，必须位于目录根部
├── index.html         入口页，路径由 entry 指定
├── main.js            脚本、样式、图片等资源，可以放在任意子目录
└── icon.svg           可选图标
```

示例（取自 `examples/minimal-plugin/manifest.json`）：

```json
{
  "id": "minimal-note",
  "name": "最小示例：便笺",
  "version": "0.1.0",
  "apiVersion": 1,
  "entry": "index.html",
  "commands": [
    { "id": "open", "title": "示例便笺", "keywords": ["便笺", "示例", "note"] }
  ],
  "permissions": []
}
```

| 字段 | 必填 | 类型 | 校验规则与说明 |
| --- | --- | --- | --- |
| `id` | 是 | 字符串 | 1～64 个小写字母、数字或中划线。它是存储命名空间和安装目录名，发布后不要修改 |
| `name` | 是 | 字符串 | 不能为空白；显示在搜索结果和插件管理中 |
| `version` | 是 | 字符串 | 不能为空白；宿主不解析格式，建议使用语义化版本 |
| `apiVersion` | 是 | 数字 | 插件依赖的协议主版本，当前只能为 `1` |
| `entry` | 是 | 字符串 | 入口页的包内相对路径，必须是已存在的文件 |
| `icon` | 否 | 字符串 | 包内相对路径；仅支持 SVG、PNG、JPEG、WebP，不超过 256 KB。省略时显示通用插件图标 |
| `commands` | 是 | 数组 | 1～20 个命令，每个命令都会作为一条搜索结果 |
| `commands[].id` | 是 | 字符串 | 规则同插件 `id`，插件内不能重复；完整命令标识为 `插件id:命令id` |
| `commands[].title` | 是 | 字符串 | 不能为空白；搜索结果标题 |
| `commands[].keywords` | 是 | 字符串数组 | 可以是空数组，但不能包含空白项；搜索时与插件名称、命令标题一起匹配 |
| `commands[].suggestedShortcut` | 否 | 字符串 | 仅作提示，宿主不会自动注册 |
| `permissions` | 是 | 字符串数组 | 可以是空数组；取值只能是 `clipboard.readText`、`clipboard.writeText`、`clipboard.history`、`hosts.read`、`hosts.write`，含义见第 6 节 |

其他规则：

- 描述文件为 UTF-8 JSON，不超过 64 KB；未列出的字段会被忽略。
- `entry`、`icon` 以及页面引用的资源必须是包内相对路径：不能为空、不能是绝对路径、不能含 `..`，解析真实路径后也不能指向包外（包括经符号链接指向包外）。
- 任一校验失败时该插件不加载，插件管理中显示中文错误原因；其他插件不受影响。

### 3. 安装与调试

- 安装：打开设置（菜单栏图标菜单中的“设置与插件”，或在主搜索框按 `⌘,`）→“插件管理”→“本地导入”，选择包含 `manifest.json` 的目录。宿主把目录复制到应用数据目录下的 `plugins/<id>/`，之后运行的是这份副本。与自带插件 `id` 相同时，本地副本覆盖自带版本。
- 导入限制：整个目录不超过 64 MB、5000 个文件和目录；不能包含符号链接或特殊文件。以 `.` 开头的目录不会被当作插件加载。
- 更新：修改源目录后重新“本地导入”同一目录，覆盖已安装副本。插件的存储数据和快捷键绑定与插件包分开保存，更新或重新加载不会丢失。
- 停用：插件管理中的开关。停用或重新加载时，正在运行的实例立即作废。
- 移除：本地插件行中的红色“移除”按钮，确认后调用主入口命令 `remove_plugin({ id })`。只删除应用数据目录中的安装副本，保留原始导入目录、插件存储数据和快捷键配置；注销运行中的快捷键并作废插件实例。内置插件只能停用；移除同标识的本地覆盖版本后恢复内置版本。刷新失败时恢复安装副本。
- 浏览器调试：可以用 `tests/plugin-host-mock.js` 在普通浏览器中模拟宿主，写法见 `tests/minimal-plugin.browser.html`。注意模拟宿主为便于检查插件 DOM 未加 `sandbox`，沙箱限制须在轻匣中复核。

### 4. 运行环境

**沙箱 iframe**：`<iframe sandbox="allow-scripts" allow="">`，地址为 `qingbox-plugin://localhost/<实例令牌>/<entry>`。

- 插件页面是不透明来源（opaque origin）：`localStorage`、`sessionStorage`、`IndexedDB`、Cookie 不可用（访问会抛出安全错误）；`navigator.clipboard` 不可用。持久化数据请用 `storage.*`，读取和复制纯文本请用 `clipboard.readText` / `clipboard.writeText`。
- 没有 `allow-forms`、`allow-popups`、`allow-modals`、`allow-top-navigation`：不能提交表单、打开新窗口、使用 `alert` / `confirm` / `prompt`，也不能导航宿主页面或访问 `window.parent.document`。
- 插件与宿主页面共用网页进程，插件长时间占用主线程会拖慢整个轻匣界面；耗时计算请分片执行或使用可行的替代方案。

**资源路径**：页面中所有资源必须使用相对路径（如 `main.js`、`./assets/app.js`）。以 `/` 开头的绝对路径会丢失实例令牌段，请求被拒绝（HTTP 403）。使用 Vite 打包时设置 `base: "./"`。

**资源类型**：按扩展名返回 `Content-Type`：`.html`、`.js`、`.css`、`.svg`、`.png`、`.json`、`.woff2` 有对应类型，其余一律为 `application/octet-stream`。因此脚本请使用 `.js`（`.mjs` 模块脚本会因类型不符被拒绝执行），字体请使用 WOFF2。资源响应带 `Access-Control-Allow-Origin: *`，Vite 产物的 `<script type="module" crossorigin>` 可以正常加载。

**插件 CSP**（每个资源响应都附带）：

```text
default-src 'none'; script-src qingbox-plugin://localhost; style-src qingbox-plugin://localhost 'unsafe-inline'; img-src qingbox-plugin://localhost data:; font-src qingbox-plugin://localhost; connect-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'
```

由此：脚本只能来自包内文件，不允许内联 `<script>`、内联事件属性（如 `onclick="..."`）和 `eval` / `new Function`；样式可以内联；图片只能是包内文件或 `data:` 地址；不能发起网络请求（`fetch`、XHR、WebSocket 等），不能嵌套 iframe。

**外观与尺寸**：面板背景由宿主统一绘制（macOS 26 起为 Liquid Glass），插件文档及根容器背景必须透明，不要铺整块底色；侧栏、底栏、卡片等分区使用低不透明度的半透明色，以透出面板材质并与主入口保持一致。内容区宽度随屏幕变化（不小于约 900 逻辑像素），高度约 610 逻辑像素，页面应按 100% 宽高自适应。

**键盘与焦点**：

- iframe 内的按键不会冒泡到宿主页面。按 `Esc` 返回搜索等宿主行为需要插件自己调用 `view.back`。焦点在插件内时，宿主页面自己的快捷键（如 `⌘,`）不生效。
- `⌘X`、`⌘C`、`⌘V`、`⌘A`、`⌘Z` 由系统“编辑”菜单作用于插件内的输入控件，插件无需处理。
- 宿主显示插件时只能聚焦 iframe 本身。插件应在收到 `view.shown` 事件时自行聚焦输入框或编辑器；页面加载时的自动聚焦并不可靠。

**生命周期**：

1. 用户打开命令后，宿主生成新的实例令牌并加载 iframe；加载期间 iframe 不可见。
2. iframe 每次触发 `load`（包括插件自行刷新页面）后，宿主重新握手并转移一个新端口，旧端口作废。
3. 插件完成界面准备后调用 `view.ready`，宿主随即显示面板并发送 `view.shown`。打开命令后 8 秒内未调用 `view.ready` 的实例会被作废，用户看到“插件加载超时，请重新打开”。
4. 返回搜索（`view.back`）、隐藏（`view.hide`）或面板失焦隐藏时，iframe 与页面状态保留；再次打开同一命令不会重新加载，只会再收到一次 `view.shown`。
5. 同一时间只有一个插件实例。打开其他插件或同一插件的另一个命令、停用插件、重新加载插件时，旧 iframe 被销毁、令牌作废；此后旧实例的调用得到 `permission_denied`（“插件实例已失效”），迟到的响应被丢弃。

### 5. 消息格式

所有消息都是可结构化克隆的普通对象。宿主会把请求参数转成 JSON 交给 Rust，因此 `params` 中只应包含 JSON 可表示的值（字符串、数字、布尔、`null`、数组、普通对象）。

**握手**（宿主 → 插件，经 `window.postMessage`，附带一个 `MessagePort`）：

```json
{ "qingbox": "init", "protocol": 1, "theme": "light", "locale": "zh-CN" }
```

- 插件只接受满足以下全部条件的第一条消息：`event.source === window.parent`、`qingbox === "init"`、`protocol === 1`、`event.ports[0]` 存在。握手后移除窗口 `message` 监听，此后只经该端口收发；宿主不处理插件发往窗口的消息。
- `theme`：`"light"` 或 `"dark"`，跟随系统外观。
- `locale`：当前固定为 `"zh-CN"`。
- `command`（可选，2026-09-24 新增）：本次打开所用的命令 ID，即清单 `commands[].id`。一个插件注册多个命令时，可据此直接定位到对应界面；同一插件换一个命令打开时，宿主会新建实例，并以新命令重新握手。SDK 中通过 `qingbox.view.command()` 取得，浏览器预览时为 `null`。
- 两个字段在类型上是可选的；缺失时插件按 `"light"`、`"zh-CN"` 处理。

**请求**（插件 → 宿主，经端口）：

```json
{ "id": 1, "method": "storage.get", "params": { "key": "note" } }
```

- `id`：数字，由插件生成，在当前页面内唯一（SDK 从 1 递增），用于匹配响应。没有数字 `id` 的消息会被宿主忽略且不回复。
- `method`：方法名，见第 6 节。
- `params`：可选，必须是普通对象；省略时按 `{}` 处理。`method` 不是字符串或 `params` 不是普通对象（如数组、`null`）时，宿主回复 `invalid_params`（“插件请求格式不正确”）。

**响应**（宿主 → 插件，经端口）：

```json
{ "id": 1, "ok": true, "result": { "text": "上次保存的内容" } }
{ "id": 2, "ok": false, "error": { "code": "invalid_params", "message": "存储键不正确" } }
```

- 每个合法请求恰好得到一个响应；多个请求并发时响应可能乱序，按 `id` 匹配。无返回值的方法 `result` 为 `null`。
- 宿主不设超时。`hosts.save` 需要等待用户完成系统授权，可能持续数分钟；插件如需超时，请自行实现。

**宿主事件**（宿主 → 插件，经端口）：`{ "event": "<名称>", "payload": <载荷> }`。

| 事件 | 载荷 | 时机与插件应做的事 |
| --- | --- | --- |
| `view.shown` | 无 | 每次显示插件时（首次 `view.ready` 之后，以及再次打开同一命令时）。插件应聚焦自己的输入区 |
| `theme.changed` | `{ "theme": "light" \| "dark" }` | 系统外观变化时。插件应切换配色 |

插件应忽略不认识的事件。宿主不会向插件发送请求。

### 6. 方法清单

以下错误码均指该方法特有的情况；所有方法还可能得到第 7 节所列的通用错误。“基础”表示无需在 `permissions` 中声明。

**视图**（基础）

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `view.ready` | 无 | `null` | 界面准备好后调用，宿主显示面板并发送 `view.shown`。每个页面只需调用一次；面板可见时重复调用会再收到一次 `view.shown` |
| `view.back` | 无 | `null` | 返回主搜索框，插件实例保留 |
| `view.hide` | 无 | `null` | 隐藏整个面板并把焦点交还之前的应用，插件实例保留 |
| `view.drag` | 无 | `null` | 开始拖动面板。须在鼠标按下（`mousedown`）处理中调用；失败为 `internal` |

**存储**（基础）：每个插件一个独立命名空间，按插件 `id` 划分，同一插件的各命令共享。

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `storage.get` | `{ key: string }` | 已保存的 JSON 值；不存在时为 `null` | `key` 为 1～128 字节（UTF-8）的字符串，否则 `invalid_params`（“存储键不正确”）；读取失败为 `internal` |
| `storage.set` | `{ key: string, value: 任意 JSON 值 }` | `null` | 覆盖写入。`key` 规则同上；缺少 `value`（包括值为 `undefined`）为 `invalid_params`（“缺少保存内容”）；序列化后超过 16 MB 为 `invalid_params`；写入失败为 `internal` |

存储没有删除接口；需要清除时写入 `null`，`storage.get` 对 `null` 与不存在的键同样返回 `null`。

**快捷键**（基础）：读写“当前打开的命令”的系统全局快捷键，按下后打开该命令。

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `shortcuts.get` | 无 | 字符串或 `null` | 未绑定时为 `null` |
| `shortcuts.set` | `{ shortcut: string \| null }` | `null` | 修饰键与按键以 `+` 连接，如 `"Alt+Shift+V"`、`"Super+Shift+J"`（`Super` 即 `⌘`）。`null`、空字符串或非字符串值表示解除绑定。先注册新快捷键再保存；失败时保留旧绑定。已被轻匣其他命令占用、格式无法识别或被系统拒绝时为 `internal`，`message` 说明原因 |

**剪贴板文本**（分别要求 `clipboard.readText` / `clipboard.writeText` 权限）

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `clipboard.readText` | 无 | `string` | 读取当前系统剪贴板中的纯文本；权限不足为 `permission_denied`；没有文本时返回中文错误，不读取历史、图片或文件 |
| `clipboard.writeText` | `{ text: string }` | `null` | 把纯文本写入系统剪贴板。`text` 不是字符串为 `invalid_params`；写入失败为 `internal` |

**剪贴板历史**（权限 `clipboard.history`，宿主系统服务；只要有已启用插件声明该权限，宿主就会每 500 毫秒采集一次系统剪贴板）

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `clipboard.list` | `{ kind: "all" \| "text" \| "image" \| "file", since?: number }` | `ClipboardSnapshot` | `kind` 缺失或取值不对为 `invalid_params`（“剪贴板分类不正确”）。`since` 传上次得到的 `revision`；历史未变时返回的 `items` 为 `null` |
| `clipboard.copy` | `{ id: number }` | `null` | 把历史记录按原类型写回系统剪贴板，并把该记录移到最前。`id` 不是正整数为 `invalid_params`；记录已被清理为 `not_found`（“记录已经过期，请选择其他记录”）；文件记录中任一文件已不存在为 `not_found`（“文件已移动或删除：<路径>”），此时系统剪贴板保持不变；其他失败为 `internal` |

```ts
interface ClipboardSnapshot {
  revision: number;                 // 历史版本号，历史变化时递增
  items: ClipboardRecord[] | null;  // 最多 200 条，按最近使用倒序；since 与当前版本相同时为 null
  counts: { text: number; image: number; file: number };
  notice: string | null;            // 最近一次采集失败的中文说明
}
interface ClipboardRecord {
  id: number;
  kind: "text" | "image" | "file";
  preview: string;          // 文本前 800 个字符；图片为“宽 × 高”；文件为文件名列表
  createdAt: number;        // 毫秒时间戳
  bytes: number;
  width: number;            // 仅图片有意义，其余为 0
  height: number;
  thumbnail: string | null; // 图片的 PNG 缩略图 data 地址（最长边 240px）
  files: string[];          // 仅文件记录：绝对路径列表
}
```

**Hosts**（宿主系统服务，仅 macOS；`hosts.get` 需要 `hosts.read`，`hosts.save` 需要 `hosts.write`）

| 方法 | 参数 | 返回 | 说明与错误 |
| --- | --- | --- | --- |
| `hosts.get` | 无 | `HostsSnapshot` | 读取分组和系统 hosts 原文。另一次保存正在进行时为 `internal`（“正在应用 Hosts，请稍后再试”）；读取失败为 `internal` |
| `hosts.save` | `{ groups: HostsGroup[], version: string }` | `HostsSnapshot`（`notice` 为结果说明） | 见下文 |

```ts
interface HostsGroup { id: string; name: string; content: string; enabled: boolean }
interface HostsSnapshot {
  groups: HostsGroup[];
  systemHosts: string;    // 系统 hosts 完整原文，只读
  version: string;        // 保存时原样传回，用于检测外部修改
  synced: boolean;        // 已启用分组是否与系统文件一致
  notice: string | null;  // hosts.get 为 null；hosts.save 为“分组已保存”“已应用，原 hosts 已自动备份”等
}
```

`hosts.save` 用 `groups` 整体替换分组；所有已启用分组合并写入系统 hosts 中的轻匣管理段。已启用分组没有变化（只改了停用分组）时不写系统文件，只保存本地配置；停用分组允许暂存尚未写完的内容。需要写入系统文件时，宿主隐藏面板并弹出 macOS 管理员授权，完成后恢复插件。错误码：

| 情况 | 错误码 |
| --- | --- |
| 参数结构不对（缺字段、类型不对或出现未定义的字段） | `invalid_params`（“Hosts 分组参数不正确”） |
| 分组不合法：标识须为 1～64 个字母、数字或中划线且不重复；名称 1～60 个字符、不含换行；最多 100 个分组、内容合计不超过 256 KB；已启用分组须为合法的“IP 域名…”行，且同一域名同一协议不能指向不同 IP | `invalid_params`，`message` 指出具体分组和行号 |
| `version` 已过期：读取后系统 hosts 或分组被修改 | `invalid_params`（“系统 hosts 或分组已发生变化，请刷新后再保存；本次未写入”） |
| 授权或写入期间系统 hosts 被外部修改，本次未写入或分组状态未提交 | `invalid_params` |
| 用户在系统授权对话框中取消 | `cancelled`（“已取消系统授权，分组启用状态未改变”） |
| 另一次保存正在进行 | `internal`（“正在应用 Hosts，请勿重复操作”） |
| 系统 hosts 中轻匣管理标记损坏、文件读写或备份失败等 | `internal` |

收到 `invalid_params` 的版本冲突后，插件应重新 `hosts.get` 并提示用户确认后再保存。

### 7. 错误码与版本规则

失败响应的 `error.code` 取以下稳定值之一；`error.message` 为中文，可直接展示给用户，但文案可能调整，程序逻辑只应依据 `code`。

| 错误码 | 含义 | 当前出现的情况 |
| --- | --- | --- |
| `permission_denied` | 无权执行 | 未在 `permissions` 中声明所需权限；实例令牌已作废（“插件实例已失效”） |
| `invalid_params` | 请求参数不正确或已过期 | 消息格式不对、参数缺失或类型不对、超出大小限制、Hosts 版本冲突或外部修改 |
| `unsupported_method` | 宿主不认识该方法 | 方法名拼写错误，或宿主版本较旧；可用于功能探测 |
| `not_found` | 目标不存在 | 插件已被移除；剪贴板记录已过期；剪贴板文件记录中的文件已移动或删除 |
| `cancelled` | 用户主动取消 | 用户在系统授权对话框中取消 Hosts 写入 |
| `timeout` | 超时 | 预留，当前宿主不返回 |
| `internal` | 宿主内部错误 | 系统服务读写失败、正在处理另一请求、快捷键注册失败等其他情况 |

通用错误：任何方法都可能得到 `permission_denied`（实例已作废）、`not_found`（插件已被移除）或 `internal`（宿主状态异常；无法识别的宿主异常消息以“宿主处理插件调用失败：”开头）。

版本规则：

- `manifest.json` 的 `apiVersion` 与握手中的 `protocol` 都是协议主版本，当前宿主只支持 `1`。不支持的 `apiVersion` 会导致插件加载失败（“不支持此插件接口版本，当前仅支持 apiVersion 为 1”）。插件应只接受自己认识的 `protocol`。
- 同一主版本内只增不改：宿主可以新增方法、可选参数、返回字段和事件；删除方法或改变已有语义必须升级主版本。已发布插件不需要因宿主升级而重新构建。
- 为兼容以后的宿主，插件应忽略不认识的返回字段和事件，把不认识的错误码按 `internal` 处理；调用较新的方法前，可以直接调用并在得到 `unsupported_method` 时降级。

### 8. 接入方式

**不使用 SDK**：直接实现第 5 节的消息格式，无需任何依赖和构建工具。核心代码约 30 行，完整可运行版本见 `examples/minimal-plugin/main.js`：

```js
let port = null, nextId = 1;
const pending = new Map();

function call(method, params = {}) {
  return new Promise((resolve, reject) => {
    const id = nextId++;
    pending.set(id, { resolve, reject });
    port.postMessage({ id, method, params });
  });
}

window.addEventListener("message", function onInit(event) {
  const data = event.data;
  if (event.source !== window.parent || data?.qingbox !== "init" || data.protocol !== 1 || !event.ports[0]) return;
  window.removeEventListener("message", onInit);
  port = event.ports[0];
  port.onmessage = ({ data }) => {
    if (typeof data?.id === "number") {
      const entry = pending.get(data.id);
      if (!entry) return;
      pending.delete(data.id);
      if (data.ok) entry.resolve(data.result);
      else entry.reject(Object.assign(new Error(data.error.message), { code: data.error.code }));
    } else if (data?.event === "view.shown") {
      document.querySelector("textarea").focus();
    }
  };
  // 握手完成：读取数据、准备界面，然后请求显示
  call("storage.get", { key: "note" }).then(() => call("view.ready"));
});
```

**使用 SDK**：SDK 源码位于 `packages/plugin-sdk/src/`（`index.ts`、`transport.ts`、`protocol.ts`），以 TypeScript 源码形式随插件一起打包，目前未发布为 npm 包；把该目录复制到插件工程中或按相对路径引用，用 Vite 等支持 `.ts` 扩展名导入的打包工具构建，并设置 `base: "./"`。

```ts
import { qingbox, QingboxError } from "./plugin-sdk/src/index";

const off = qingbox.events.on("view.shown", () => editor.focus());
qingbox.events.on<{ theme: "light" | "dark" }>("theme.changed", ({ theme }) => applyTheme(theme));
const draft = await qingbox.storage.get<{ text: string }>("note");
await qingbox.view.ready();
try {
  await qingbox.storage.set("note", { text: editor.value });
} catch (error) {
  if (error instanceof QingboxError) showError(error.message, error.code);
}
```

| SDK 接口 | 协议方法 |
| --- | --- |
| `qingbox.view.ready()` / `back()` / `hide()` / `startDragging()` | `view.ready` / `view.back` / `view.hide` / `view.drag` |
| `qingbox.storage.get(key)` / `set(key, value)` | `storage.get` / `storage.set` |
| `qingbox.shortcuts.get()` / `set(shortcut)` | `shortcuts.get` / `shortcuts.set` |
| `qingbox.clipboard.readText()` | `clipboard.readText` |
| `qingbox.clipboard.writeText(text)` | `clipboard.writeText` |
| `qingbox.clipboard.list(kind, since?)` / `copy(id)` | `clipboard.list` / `clipboard.copy` |
| `qingbox.hosts.get()` / `save(groups, version)` | `hosts.get` / `hosts.save` |
| `qingbox.events.on(event, callback)`，返回取消订阅函数 | 宿主事件 |

SDK 行为说明：

- 页面位于 iframe 中时等待宿主握手，握手前发起的调用会排队，握手后依次发送；宿主返回失败时抛出 `QingboxError`，带 `code` 与中文 `message`。SDK 不设超时。
- 页面作为顶层窗口直接打开时视为浏览器预览：`view.*` 不调用宿主（`back` 执行 `history.back()`），`storage.*` 改用带 `qingbox-json-preview:` 前缀的 `localStorage`，`clipboard.writeText` 使用 `navigator.clipboard`，`shortcuts.get` 返回 `null`；Hosts、剪贴板历史和 `shortcuts.set` 抛出普通 `Error`，事件不会触发。

### 9. 最小示例插件

`examples/minimal-plugin/` 是一个不依赖 React、SDK 和构建工具的便笺插件，只有三个文件：`manifest.json`、`index.html`、`main.js`。它完成握手、从 `storage` 读取上次内容、调用 `view.ready`，收到 `view.shown` 时聚焦编辑区，响应 `theme.changed`，`⌘S` 保存到 `storage`，`Esc` 调用 `view.back`，并展示宿主返回的错误码和中文消息。

- 在轻匣中运行：设置 →“插件管理”→“本地导入”，选择 `examples/minimal-plugin` 目录，然后在主搜索框输入“便笺”。
