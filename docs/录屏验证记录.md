## 系统 API 与媒体

本机系统：macOS 27.0（26A428）。只使用执行环境已有的屏幕录制与麦克风授权，探针不请求新权限。

探针录制主屏左上 640 × 360 点区域，输出 640 × 360 像素，设置最小帧间隔 1/30、BGRA、SDR、显示光标与点击圆圈。每段捕获约 3 秒，等输出完成通知后用 `ffprobe` 检查。

| 配置 | 原始文件结果 | 结论 |
| --- | --- | --- |
| 系统声音关闭、麦克风关闭 | H.264，无音轨；原生返回 3 秒，但静止画面文件仅 0.066667 秒、1 帧 | 确认默认无音轨；发现静止尾段缺失，需补齐后再验收 |
| 仅系统声音 | H.264 与双声道 AAC，文件约 3.179 秒 | 确认系统声音开关改变实际音轨；未证明声音内容与长时间同步 |
| 仅麦克风 | H.264 与双声道 AAC，文件约 3.317 秒 | 确认麦克风开关改变实际音轨 |
| 系统声音与麦克风 | H.264 与单条双声道 AAC，文件约 3.208 秒 | 本机系统合成到一条音轨；不承诺独立双音轨 |

上述四种原始 MP4 均通过 `ffprobe` 读取与 `ffmpeg` 完整解码。声音内容、播放器操作与长时间同步仍待应用真机验收。

原始静音文件在独立无界面 Chrome 的 `<video>` 中同样返回 `duration = 0.066667`，没有加载错误；与 `ffprobe` 一致。AVFoundation 读到的轨道范围较长，不能仅凭原生时长属性宣告文件时长正确。

静止画面不持续产生新帧，最小帧间隔只限制更新频率。静音时长修复不能通过隐式开启任何声音实现，输出文件处理完成前应继续处于收尾状态。

静音文件处理已接入生产同一 Objective-C 桥，并独立编译验证：原静音单帧修复为 3 秒；重排视频全部 PTS/DTS 和逐帧像素保持；实际动态后静止的系统输出已为 3.333333 秒，处理逐字节跳过，没有缩短。独立 Chrome 读到修复后的 3 秒且无加载错误，重排片的新增尾段显示最后画面。处理只在本次两种声音都关闭、流与输出均终结后执行，完成前保持收尾；失败保留原文件并提示。
